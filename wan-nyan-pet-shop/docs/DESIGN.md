# 設計メモ

「わんニャンペットショップ かわいいペットとふれあう毎日」を題材にした、
ふれあい＋やりくりのゲームです。ここでは何をどう決めたかを残します。

## 1. コアループ

```
      ┌──────────────── 夜（自動）────────────────┐
      │                                          │
  開店（120秒）  →  せいさん  →  お店のじゅんび  →  翌日
      │
      ├─ お世話する（ごはん／ブラシ／あそぶ／なでる）→ コンディションとなつき度が上がる
      ├─ おそうじする → 店内のきれいさが戻る → 来店ペースが上がる
      └─ お客さんが来る → 条件を満たした子をおむかえ → お金と評判
```

プレイヤーの行動は「どの子に、どの世話を、いつするか」の一点に集約されています。
道具にクールダウンがあり、ペットが増えるほど手が回らなくなる——これが難易度の実体です。

## 2. 数値の考えかた

すべて `src/game/balance.js` に集約しています。1 日 = 120 秒。

| 欲求 | 減り方 | 1日あたり | 回復手段 |
|---|---|---|---|
| おなか | 0.75 /秒 | −90 | ごはん +46（40円・CD 6秒） |
| きれい | 0.42 /秒 | −50 | ブラシ +44（無料・CD 5秒） |
| げんき | 0.5 /秒 ×性格 | −60 前後 | 睡眠（自動）・夜あけ +45 |
| なつき | 0.07 /秒 | −8 | なでる +5 / あそぶ +11（性格補正あり） |
| けんこう | 空腹または汚れが 22 未満で −1.15 /秒 | — | 良い状態で +0.45 /秒 |

つまり **1 匹あたり 1 日 2 回のごはんと 1 回のブラシが最低ライン**。
ベッドを 6 つまで増やせるので、最大では 1 日 18 回のお世話が必要になります。
プレイヤーの手が足りなくなる地点をここに置きました。

### お金

| 項目 | 金額 |
|---|---|
| 開始所持金 | 1,500円 |
| ごはん | 40円 |
| 家賃 | 180円 + 1匹あたり 55円 |
| 動物病院 | 600円 |
| 新しい子のおむかえ | 500円 |
| おむかえの相場 | 犬 940円 / 猫 880円 を基準に、コンディション・なつき度・評判・店内のきれいさ・客の予算で 0.6〜1.7 倍 |

自動プレイのボット（`tests/unit/longplay.test.mjs`）で 10 日間の収支を検証しています。
きちんと世話をすれば 1 日 1,000〜4,000円の黒字、放置すれば赤字で閉店します。

### 評判

* おむかえ 1 件につき +4 前後（状態が良いほど増える）
* 何も選ばずに帰られると −2.5
* 1 日の終わりに「平均コンディション −55」÷10 を加算（世話の質がそのまま効く）
* 100 に到達でエンディング。以降も継続可能（上限 200）

## 3. なぜこの設計にしたか

### ロジックを DOM から完全に切り離した

`src/game/**` は `document` も `canvas` も参照しません。結果として:

* ユニットテストがブラウザなしで動く（85 件が約 1 秒）
* 10 日ぶんのプレイをテスト内で丸ごと再生できる → バランス変更が壊れたら即わかる
* 描画を差し替えてもゲームの挙動は変わらない

### 固定タイムステップ + 決定的乱数

シミュレーションは 30 Hz 固定。描画は可変。
乱数は状態をシリアライズできる mulberry32 で、シードから完全に再現できます。
「同じシードなら同じ展開」がテストで保証されているので、バグの再現が容易です。

タブを長時間隠したあとの復帰では、1 フレームで進めるステップ数を 5 に制限しています
（`src/core/loop.js`）。これがないと復帰時に数千ステップを一気に処理して固まります。

### 演出はイベント購読

`state.js` は `bus.emit('adopt', …)` のようにイベントを流すだけで、
音もパーティクルも知りません。`main.js` がそれを購読して効果音とハートを出します。
テストではバスを渡さない（または捨てる）だけで演出を無効化できます。

### アセットを持たない

犬猫は犬種テーブルの数値（毛色・耳・尻尾・もふもふ度・大きさ）から手続き的に描いています。
新しい犬種を足すのは `src/game/data.js` に 1 行足すだけです。
効果音も同様に、オシレータとノイズから合成しています（鳴き声は犬＝のこぎり波の下降、
猫＝上昇するフィルタ）。ダウンロードが 0 なので初回表示が速く、オフラインでも動きます。

## 4. 画面レイアウト

論理解像度 960×600 固定、CSS 側でアスペクト比を保ったまま拡縮します。
`devicePixelRatio` は 2 で頭打ちにしています。

```
 0        上部バー（58px）: 日数 / 営業時間 / 所持金 / 評判 / きれいさ / 匹数 / 操作
58 ┌──────────────────────────────────────────┐
   │ 選択中ペットのカード（左上・幅226）        │  壁：時計・窓・棚・看板・ドア
268│──────────────────────────────────────────│
   │ 床：ベッド・ラグ・ペット・お客さん・よごれ  │
476│──────────────────────────────────────────│
508│ 道具バー（5つ）                            │
600└──────────────────────────────────────────┘
```

UI もキャンバスに直接描き、クリック判定は毎フレーム作り直す矩形リスト（`Regions`）で行います。
DOM を使わないのでレイアウト計算が発生せず、E2E テストからは領域 ID を指定して
実際のマウスでクリックできます。

## 5. 意図的にやらなかったこと

* **ペットが死ぬ演出** — けんこうが 0 になったら動物病院で回復します。かわいさが主題のゲームで、
  取り返しのつかない喪失は入れませんでした。代わりに費用と評判で罰します。
* **おむかえの拒否** — お客さんに「この子は渡さない」と断る操作は入れていません。
  操作が増える割に、店として成立しなくなるためです。旅立った子は「アルバム」に残ります。
* **ビルドツール** — バンドラを入れると `npm install` が必要になります。
  ES モジュールをそのまま配信すれば十分な規模なので、依存ゼロを優先しました。
